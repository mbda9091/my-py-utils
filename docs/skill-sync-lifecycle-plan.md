## 1. 结论摘要

- `install --force`：允许将指定同名目录先完整备份，再替换为指向个人仓库的软链接。备份成功后长期保留，输出完整路径，不自动清理。
- 安装和卸载统一使用当前用户的 `~/.agents/skills`，移除 `--target`，不增加其他客户端或安装目录配置。
- `uninstall <name>`：删除这个使用位置上的个人技能链接，保留仓库内容及已有备份。
- `remove <name>`：删除个人仓库里的技能，并清理可确认仍指向它的使用链接，包括 `add` 留下的原始入口；Git 提交仍由用户完成。
- `update`：对已绑定的整个个人仓库执行仅允许快进的 Git pull。用户已确认这一范围；不做单个技能的独立上游管理。
- 保留单仓库配置、默认同名跳过告警、旧状态显式迁移、真实链接核验和现有进程锁。只为这些操作增加必要逻辑，不恢复 `publish/sync`。
- 当前按 M1–M4 实施，每阶段验证、回写并提交；仅使用隔离测试目录，不操作真实个人技能。

## 2. 范围

### 2.1 目标

| 目标 | 完成后用户能观察到的结果 |
|---|---|
| G1：强制安装 | 同名真实目录不再阻止显式强制安装；旧内容有可恢复备份，客户端入口变为仓库软链接 |
| G2：卸载 | 可以只停用一个客户端技能入口，仓库技能仍可再次安装 |
| G3：删除 | 可以删除仓库技能及其已知有效链接，其他技能和第三方内容不受影响 |
| G4：更新 | 一条命令拉取绑定仓库当前分支的上游，已有链接直接读到最新内容，异常时有明确提示 |

### 2.2 边界

- 继续只绑定一个仓库；技能真实路径为 `<repo>/skills/<name>`，安装和卸载路径固定为当前用户的 `~/.agents/skills/<name>`，从用户 home 解析，不依赖当前工作目录。
- 不支持 `--target`、自定义安装目录或项目内 `.agents/skills` 安装。`add` 仍可接受用户明确选择的已有目录并原地回链；该路径属于纳管入口，不是额外的安装目标配置。
- 本轮新增的 `uninstall/remove` 先支持单个名称，不增加批量删除、`--force` 删除或交互确认。显式执行命令及指定名称就是操作入口；不改造现有 `install --all` 参数。
- 不新增备份管理命令、自动恢复旧目录、自动清理备份、自动追踪技能重命名或全盘搜链。备份通过输出路径和元数据手动恢复。
- 不新增 Git stage、commit、push、stash、reset、分支切换、remote 配置或通用 Git 执行接口。
- 适用常规本地文件系统、Python 3.11+ 与当前 POSIX 软链接/文件锁环境。Linux 为本轮必要真实验收平台；macOS 未实测时明确记录，Windows 不作兼容承诺。
- 普通异常应回滚；SIGKILL、断电、多套状态目录同时控制同一仓库、用户同时手动改目录或运行 Git，不承诺自动事务恢复。保留可识别现场，不额外建设后台恢复系统。
- 完成定义：M1–M4 均实现，A1–A12 必要验收通过，实施提交与验收版本对账，使用说明和项目约定同步后才标记完成。

## 4. 具体方案

### 4.1 命令与操作对象

下表为本轮接口；M1 安装接口已进入实现，新增入口依次在后续阶段交付。所有命令复用已保存仓库，不增加 `--repo`。

| 命令 | 操作位置 | 成功后的状态 |
|---|---|---|
| `skill-sync install foo --force` | 用户 `~/.agents/skills/foo` | 旧入口被备份，新入口链接到 `<repo>/skills/foo` |
| `skill-sync install --all --force` | 用户 `~/.agents/skills/` 中各技能入口 | 逐技能处理，保留现有继续执行和统计行为 |
| `skill-sync uninstall foo` | 用户 `~/.agents/skills/foo` | 删除可确认属于个人技能的链接，仓库内容保留 |
| `skill-sync remove foo` | `<repo>/skills/foo` 及其已知链接 | 仓库技能删除，有效个人链接清理；Git diff 显示删除 |
| `skill-sync update` | 已绑定仓库的当前分支 | 从该分支现有 upstream 仅快进更新 |

三个名称参数均为技能名，不是路径，沿用现有名称校验。`install foo` 和 `install --all` 均不再需要目标参数；`--force` 按需使用。`uninstall/remove` 只校验名称和路径边界，不依赖有效的 `SKILL.md`，避免技能描述写坏后无法删除。`update` 不接收技能名、目标客户端、仓库 URL 或 Git 透传参数。

### 4.2 `install --force`：备份后替换

#### 同名处理矩阵

先验证仓库技能有效，再检查客户端入口。源技能无效时不移动客户端内容。

| 客户端入口 | 普通安装 | 强制安装 |
|---|---|---|
| 不存在 | 创建链接、记录 | 相同，不产生备份 |
| 已可确认直接指向当前仓库技能 | 幂等，补齐记录 | 幂等，不重复备份 |
| 普通真实目录，包括第三方同名技能 | 跳过并告警 | 完整备份这个目录，再建链接 |
| 普通文件 | 跳过并告警 | 备份文件本身，再建链接 |
| 指向其他位置的软链，包括已登记旧仓库链接、未知链接和断链 | 跳过并告警 | 只备份链接本身，再建链接；不操作其指向的内容 |
| 特殊文件、待替换目录本身为挂载点等无法安全搬移的入口 | 跳过并告警 | 保留并告警，不递归删除来强行腾位置 |

本轮将 `--force` 定义为对**指定同名入口**的显式备份替换授权，不再要求旧入口一定有个人安装记录。普通文件和未知链接也采用同一备份规则，以保持行为一致。无 `--force` 时继续保护所有冲突内容；任何旧记录都不能单独授权覆盖。

检查之后若入口身份发生变化，停止该项，不把 `--force` 扩大到刚出现的新对象。沿用现有捕获、身份复核及不覆盖发布链接的做法。

#### 持久备份位置与内容

备份位于**使用目录的同级专用目录**，默认布局如下；不要放在 `skills/` 内，避免客户端再次发现备份中的技能。

```text
~/.agents/
  skills/foo -> <repo>/skills/foo
  .skill-sync-backups/
    foo-<UTC时间>-<随机标识>/
      original                 原目录、普通文件或软链本身
      backup.json              原使用路径、类型、创建时间、安装来源
```

- 以实际规范化后的使用目录计算同级备份位置；创建唯一容器，拒绝被软链替换的备份根和容器，不覆盖已有备份。容器使用仅当前用户可访问的权限。
- 通过同文件系统 rename 保存原入口，保留完整文件树、原始软链文本和权限，不合并、不解引用软链。备份中的相对软链可能暂时不可用，恢复到原路径后恢复原有含义。
- 若使用目录单独挂载，导致移动到同级备份目录出现 `EXDEV`，该项失败并保留原入口。本轮不增加跨设备复制备份；安装源和使用目录仍可在不同文件系统，因为新入口只是软链。
- 备份不自动删除、不加入技能清单、不随 `uninstall/remove` 删除。每次确实替换入口才新增一份，输出完整备份路径。没有备份则不输出虚构路径。
- 备份元数据独立于安装记录，记录实际原入口位置，不修改配置或安装记录的 schema v2。不保存凭据或 Git 远端 URL。

#### 顺序、失败与恢复

1. 持有现有状态锁，重新读取绑定和记录，验证源技能并捕获目标身份。
2. 准备备份容器和元数据；将旧入口捕获到容器，复核其身份。备份准备失败则不建新链接。
3. 在原路径不覆盖地创建新软链，原子写入更新后的安装记录；这两步完成才算安装提交。
4. 提交前异常：撤回本次创建的链接，恢复旧入口和原记录；恢复成功时清理空事务容器。
5. 恢复位置已被占用或恢复失败：保留原备份及新占用内容，返回失败并报告恢复路径。不自动覆盖新占用，不把失败现场清掉。
6. 提交成功：保留备份并输出路径。非关键临时文件清理失败只告警，不能再次走回滚、删除已经生效的安装。

手动恢复说明需写入 README：先确认当前入口仍是安装的链接，通过 `uninstall` 移除它，再将 `original` 搬回元数据记录的原路径；遇到新占用先人工处理。恢复后该入口是原目录/链接，工具不自动纳管它。`uninstall` 本身不会恢复旧内容。

### 4.3 `uninstall`：只卸载一个客户端入口

固定处理当前用户的 `~/.agents/skills/<name>`。不遍历第三方技能，不处理当前项目的 `.agents/skills`，也不删除 `add` 在其他目录留下的入口。

| 实际状态 | 行为 |
|---|---|
| 可证明直接指向当前 `<repo>/skills/<name>` 的链接 | 删除链接；匹配记录存在则删除该条。没有记录也可凭实际指向完成卸载 |
| 记录来源明确，当前链接确实指向所记录的旧仓库同名技能 | 可以卸载该客户端旧链接，清理对应记录；不删除旧仓库内容 |
| 上述可证明的个人断链 | 同样只删除链接，源技能不存在不阻止卸载 |
| 路径已经不存在 | 幂等成功；只清理该路径、该名称且来源明确的对应记录 |
| 真实目录、文件、第三方链接，或来源无法证明的断链/别名/循环链接 | 保留入口和原记录，跳过并告警 |
| 记录来源未知，但实际链接可独立证明指向当前仓库技能 | 可按实际指向卸载；不借此推断其他旧记录的归属 |

核验使用路径父目录未被换为别名，并沿用 `symlink_target` 的可证明指向规则；不能先 `resolve()` 丢掉中间软链信息再认定归属。记录必须同时匹配名称、使用路径和来源，不能仅凭同名删除。

先将待删链接捕获到同目录私有临时位置并复核身份，再写记录；提交前失败恢复链接和记录。只对捕获的链接执行 unlink，不对使用路径执行递归删除。成功输出卸载路径；重复执行输出已不存在。实际 I/O 或状态写入失败返回非零。

### 4.4 `remove`：删除仓库技能和已知使用链接

这是破坏性删除：删除 `<repo>/skills/<name>` 的完整内容，包括未提交和未跟踪文件。显式 `remove <name>` 即表示执行删除，不自动 stash 或生成可长期恢复的技能副本；Git 已跟踪内容可由用户自行恢复，未跟踪内容无法靠 Git 恢复。CLI 帮助及 README 必须说明这一点。

#### 删除范围

1. 仓库真实技能目录：使用严格名称构造路径，要求 `skills/` 和技能根均为真实目录；拒绝将仓库内软链入口当作技能根向外删除。缺少/损坏 `SKILL.md` 不影响明确删除。
2. 所有安装记录中 `skill == <name>`、`sourcePath == 当前 <repo>/skills/<name>` 的使用路径，包括标准 agents 入口、`add` 原始回链及历史已登记路径；不按旧 `target` 标签推断删除权限。
3. 当前用户 `~/.agents/skills/<name>` 作为额外候选，即使记录丢失，只要实际直接链接到当前技能也可清理。
4. 每个候选都检查实际入口，并复用外部路径边界检查，拒绝在仓库内部或仓库祖先位置操作记录路径；仅删除仍可证明指向当前技能的软链。父级换位、旧记录、未知来源、第三方新目录或链接都不授权删除。

同名旧仓库的内容和链接不属于本次范围，保留。其他位置没有安装记录的手工链接不全盘查找，删除后可能成为断链；命令输出说明只清理记录路径及标准客户端入口。

#### 结果与事务

- 仓库技能存在、链接正常：暂存待删除的目录和链接，原子更新记录后清理暂存内容；成功后仓库路径、已验证链接和对应记录均消失。
- 仓库技能已不存在：仍可清理指向当前来源的已知断链；全部已经不存在时幂等成功。
- 使用入口被第三方内容替换：保留并告警，继续删除仓库技能；保留该条异常记录供 `status` 排查。输出分别说明仓库删除、链接删除及跳过数量，不能声称所有入口均已删除。
- 来源为当前仓库、路径确实已不存在的匹配记录可以清理；来源未知或属于其他仓库的记录保留，不推断归属。
- 实际移动/写记录失败：在提交前整体恢复本次暂存的目录、链接和原记录；不能删一半后仍报完全成功。恢复路径有新占用时不覆盖，保留暂存内容并报告位置，返回失败。
- 记录写入成功为提交点。之后清理暂存目录失败：命令成功并告警残留完整路径；可能只剩部分文件，不能称其为完整备份。再次 `remove` 不会擅自清理未知历史残留。

目录暂存放在技能父目录的唯一私有容器中，容器自身不含直接 `SKILL.md`，不被当前 catalog 当作技能。链接各自在原父目录暂存，避免跨设备移动。清理不跟随目录软链，不对挂载目录进行跨文件系统递归清理；发现不支持的边界在提交前停止。

`remove` 不等于把 `add` 前的真实目录放回原处。它按本次需求直接删除仓库技能和链接；需要保留内容时应使用 `uninstall`。

### 4.5 `update`：显式更新整个绑定仓库

用户于 2026-11-24 确认：更新已绑定的整个仓库，分叉停止，不自动合并。读取一次配置后在锁内复核，所有 Git 进程的 cwd 均固定为该仓库。

#### 前置条件

- 仓库路径有效，有当前分支和有效 HEAD，当前分支已配置单一可拉取的 upstream。没有 upstream、空仓库或 detached HEAD 时返回错误，提示用户自行配置；不猜测 `origin/main`。
- 没有进行中的 merge/rebase/cherry-pick/revert。未完成的 Git 操作交由用户处理。
- 工作区干净：暂存、未暂存及未被忽略的未跟踪文件均不允许存在。被 `.gitignore` 忽略的缓存不阻止更新。`add/remove` 后尚未提交的变化会阻止更新，提示用户先自行处理。
- 这些条件通过固定的只读 Git 查询检查；实现需列出允许的固定参数集合。预检失败不执行 pull，不修改技能和安装记录。

#### 固定更新行为

核心命令等价于以下固定调用，使用参数列表执行，不通过 shell、不拼接用户 Git 参数：

```bash
git pull --ff-only --no-rebase --no-autostash --no-recurse-submodules
```

显式禁止用户 Git 配置使工具自动 rebase/stash 或递归更新子模块。不新增通用 Git runner。继续使用用户已配置的认证、upstream 及正常 Git 环境；Git 仓库自有的 hooks/filters 仍属于用户 Git 配置，不宣称工具对它们进行沙箱隔离。

| 场景 | 预期结果 |
|---|---|
| 上游有新提交，可以快进 | 当前分支快进；已有技能链接直接读到新内容；输出仓库路径和更新前后提交 |
| 已是最新，或本地仅领先上游 | 成功，无需更新；不 push、不回退本地提交 |
| 本地与上游分叉 | 返回错误，保留本地提交；提示用户自行处理，不自动 merge/rebase/reset |
| 网络、认证、远端不存在等 pull 失败 | 返回错误并展示必要 Git 错误摘要，不保存凭据；不改安装记录，不自动重试或回退 Git |
| 拉取新增技能 | 可被 `list` 发现；不自动安装 |
| 拉取删除/重命名技能 | 原使用链接可能成为断链；告警列出已知受影响入口，不自动猜重命名或删链接，可随后 `uninstall/remove` 清理 |
| 拉取成功但技能描述错误或技能根结构非法 | 明确说明 Git 更新成功，同时逐项告警；不自动回退已拉取提交，不把单项坏技能阻塞全部输出 |

不将 Git 过程描述成文件事务：pull 失败也可能已更新对象库、FETCH_HEAD 或远端跟踪引用；hooks 等异常也可能发生在工作区已经变化之后。输出应说明实际结果，必要时报告可读取的当前 HEAD，不声称所有 Git 状态完全未变。用户自行用 Git 排查，工具不执行 reset 回滚。

- `target` 不再是用户功能或路径选择依据。为兼容现有 schema v2，历史记录的 `target` 字段原样保留；新安装记录暂沿用旧 `codex` 标签，`add` 回链沿用 `local-path`。这些只是内部兼容值，不增加新目标枚举或迁移流程，也不能单独授权修改路径。测试通过隔离 HOME 验证固定目录，不把内部测试路径注入设计成产品配置。
- 对 `uninstall/remove`，绑定仓库目录完全缺失时，允许读取已保存的 v2 配置，仅清理可证明指向该来源的已知断链，不创建仓库或技能目录。保存的路径已变为软链、路径存在却不再是有效仓库等情况仍拒绝。`install/update` 继续要求有效仓库；锁内复核不能因为清断链而跳过配置变更检查。
- `init/add/install/uninstall/remove/update` 共用同一状态目录锁，覆盖预检、实际修改、写记录和回滚；批量安装继续持有整个批次的锁。Git 拉取期间其他写命令等待，输出正在更新，避免看起来无响应。
- 锁只协调使用同一状态目录的工具进程，不替代 Git 锁或用户编辑器协调。用户在相关操作完成前避免手动变更对应入口或执行并行 Git。
- 退出码统一：成功、幂等、保护性跳过为 0，跳过写 `[WARN]`；I/O、备份、恢复、Git 更新失败为 1；参数错误为 2。批量安装沿用 installed/skipped/failed 统计，真实失败非零。
- 对新增权限/备份写入失败不能降级为悄悄删除。未完成的操作、保留路径和恢复限制必须出现在错误输出里。
