## 1. 结论摘要

- **要解决的问题**：现有CLI显式限制Linux，Windows还缺少兼容的密钥读取、路径读取和访问权限实现。
- **采用的方案**：保留压缩、配置和业务流程，将无覆盖发布、安全读取与私有文件创建封装为平台适配层。
- **本轮边界**：支持Linux、macOS及原生Windows的本地磁盘；保持配置v1、统一密码、16字节填充及默认输出规则。
- **当前进展**：已完成存储层拆分、Windows ctypes封装、原生专项测试、旧配置夹具及CI；Linux全仓173项通过，4项仅适用于其他平台而跳过。
- **下一步**：首轮原生矩阵和3×3互操作已经通过；继续审阅归档证据、补充特殊路径边界并统一正式支持文案。

## 2. 范围

### 2.1 目标

- G1：三个系统均可运行keygen、pack和decrypt-config，参数及默认行为一致。
- G2：保持输出不覆盖、链接拒绝、密钥与明文配置受限访问、失败不发布不完整批次。
- G3：同一密钥可以在不同平台解密配置；各平台创建的包能由其他平台的独立7-Zip工具正确解压。
- G4：通过自动化CI持续验证原生平台行为，记录操作系统、架构、依赖、产物及测试证据。

### 2.2 非目标与延期项

| 事项 | 本轮处理 | 原因或后续触发条件 |
| --- | --- | --- |
| 自动恢复包名、自动解压和清理填充 | 延期 | 本轮仅扩展运行平台，独立7-Zip解压仅用于测试 |
| GUI、安装器、独立exe/app | 不做 | 保留Python CLI及uv安装方式 |
| Windows ARM64 | 按需建设 | 首轮Windows以x64为目标，另有需求时增加架构证据 |
| 网络共享、FAT/exFAT、云盘占位文件 | 不纳入首轮支持承诺 | 文件语义、权限及重解析行为需要专门验证 |
| 任意文件名自动转换 | 不做 | 不静默改名；互操作夹具使用三平台合法且无冲突的名称 |
| 文件系统快照、断电恢复、全部元数据备份 | 不做 | 沿用首版边界，不提供完整备份系统保证 |

### 2.3 适用场景与协作边界

- Python运行时保持3.11+；CI拟覆盖3.11和3.14两个版本，其他版本不因声明范围而视为已测试。
- 原生目标：Linux x64、macOS Apple Silicon与Intel、Windows x64。CI具体runner标签、系统版本与资源可用性在M1确定并记录，不只记录“latest”。
- 首轮文件系统目标：Linux本地文件系统、macOS APFS、Windows NTFS；其他卷若缺少必要能力则明确失败，不回退为覆盖操作。
- WSL属于Linux测试，不能替代原生Windows；模拟平台分支也不能代替原生验收。
- 本文负责跨平台增量；首版文档作为历史行为基线。本次按用户要求单独新增本文，不回改老方案。
- 完成定义：A1–A8必要验收全部通过，各目标平台及架构具备真实证据，才可标记本轮已验收；缺少runner时记录受阻。

## 4. 具体方案

### 4.1 总体设计与职责

业务层只调用统一接口；平台代码负责原生文件系统差异，不改压缩格式或增加外层文件加密。

| 部分 | 职责 | 输入与输出 | 本轮改动 |
| --- | --- | --- | --- |
| storage.py | 对外统一文件操作接口，按平台选择实现 | 路径/内容/句柄 → 成功或明确异常 | 修改已有模块 |
| storage_posix.py | POSIX安全读取、私有权限基础能力 | 源路径 → 经检查的二进制流 | 拟新增 |
| storage_linux.py | Linux排他目录发布 | 暂存目录 → 最终目录 | 从现有实现拆出 |
| storage_macos.py | macOS排他目录发布及能力检查 | 暂存目录 → 最终目录 | 拟新增 |
| storage_windows.py | Windows句柄、重解析点、ACL及发布 | 同一接口契约 | 拟新增 |
| planning.py / workflow.py | 使用统一类型检查、私有暂存和能力预检 | 内存计划 → 完整批次 | 修改已有模块 |
| manifest.py / archive.py | 配置v1与7z加密 | 保持已有数据契约 | 复用，必要时调整文件流交接 |
| 测试和CI | 原生测试、产物传递、互操作验证 | 合成夹具 → 脱敏报告 | 修改测试，拟新增流水线 |

拟统一的内部接口：`check_capabilities`、`open_source`、`read_key`、`write_private`、
`private_temp_directory`、`commit_directory`及扫描用的类型/链接检查。
Windows相关模块只在Windows导入，避免Linux/macOS导入时访问不存在的API。

### 4.2 关键行为与异常路径

#### 4.2.1 无覆盖发布

| 平台 | 拟使用能力 | 失败语义 |
| --- | --- | --- |
| Linux | 保留renameat2(RENAME_NOREPLACE) | 目标存在或系统不支持则失败 |
| macOS | renamex_np(RENAME_EXCL) | 卷或系统不支持排他重命名则失败 |
| Windows | os.rename的目标存在报错语义；必要时封装无替换标志的MoveFileExW | 目标存在、被占用或操作失败则报错，不替换 |

暂存与输出仍位于同一父目录、同一文件系统。预检之后目标才出现也不得覆盖。
不得使用“exists检查后普通POSIX rename”替代排他操作；不得回退成跨卷复制或覆盖式replace。
文件系统能力尽可能在耗时打包前用私有临时夹具探测；实际提交仍处理原生错误。
本轮验证进程正常运行时的发布语义，不将单次目录重命名解释为断电持久性保证。

macOS排他重命名能力见[Apple文档](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming)。
Windows的os.rename目标存在报错见[Python文档](https://docs.python.org/3/library/os.html#os.rename)，
原生目录移动限制见[Microsoft文档](https://learn.microsoft.com/en-us/windows/win32/fileio/moving-directories)。

#### 4.2.2 源文件与密钥读取

- Linux/macOS继续逐组件打开目录，拒绝跟随链接，在实际读取前后校验文件身份与变化信息。
- Windows使用原生文件句柄；扫描阶段识别重解析点，实际打开时再次校验。仅检查is_symlink不足以处理junction。
- FILE_FLAG_OPEN_REPARSE_POINT只针对相应打开对象，不能当作自动保护整条路径。父级目录也需检查并通过持有句柄等方式防止读取过程中被替换；具体共享模式和句柄生命周期在M1原型验证。
- 首轮拒绝不支持的重解析点，不自动进入junction或触发未知云端内容读取。错误要说明不支持的对象类型。
- 保持不允许将密钥或其硬链接纳入输入；Windows身份比较使用可靠的文件ID/卷身份，不假定所有平台st_ino语义完全一致。
- 读取内容的句柄转换成Python二进制流时，明确所有权，保证只关闭一次；异常路径释放全部目录和文件句柄。

依据：[Windows重解析点与文件操作](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points-and-file-operations)。
不承诺对恶意并发修改整棵目录提供完整快照，但不能因跨平台适配而取消已有链接拒绝边界。

#### 4.2.3 密钥、配置与暂存访问权限

- POSIX保留0600文件、0700目录，并检查目标环境扩展ACL继承是否破坏预期访问范围。
- Windows在创建文件/目录时传入受限安全描述符，控制DACL继承，限制为当前用户及明确记录的系统主体；不能先写敏感数据再收紧权限。
- `keygen`、解密配置输出、批次暂存目录统一走私有创建接口，均拒绝覆盖已有对象。
- Windows不支持所需ACL的文件系统明确报错。权限保护不意味着能阻止管理员接管权限。
- Windows原生调用优先集中封装，M1比较ctypes与仅Windows条件依赖的维护成本后定案；不为Linux/macOS引入不必要的Windows运行依赖。

Windows支持在创建文件或目录时提供安全描述符，见[文件安全文档](https://learn.microsoft.com/en-us/windows/win32/fileio/file-security-and-access-rights)。

#### 4.2.4 路径、名称和清理

- 输入支持中文、空格、相对路径、绝对路径及`.`，包内路径统一使用相对POSIX格式。
- Windows处理盘符、文件占用和路径长度错误；根目录输入继续要求显式输出。UNC/网络共享不属于首轮验收范围。
- 不静默改写源文件名。跨系统合法名称以外的保留名、大小写冲突、Unicode规范化差异与尾随空格等，记录为互操作边界；测试应验证可诊断失败而非静默覆盖。
- 正常失败清理本批暂存；Windows先释放句柄再清理，因占用仍无法删除时报告残留位置，不假报清理成功。
- 最终批次只在全部包与加密配置就绪后出现，源内容保持不变。

### 4.3 接口、配置与使用方式

以下命令已接入三个平台的实现，并通过本轮原生CI；范围外的文件系统和路径边界不因此获得支持承诺。
安装后在用户工作目录执行，`secrets`与`input`先存在，密钥在输入之外，输出不得已存在：

```text
private-pack keygen --output ./secrets/master.key
private-pack pack ./input --key-file ./secrets/master.key
private-pack decrypt-config ./input-packed/manifest.enc --key-file ./secrets/master.key --output ./secrets/manifest.json
```

省略pack的--output仍生成同级input-packed；显式--output优先。配置schema、二进制封装、
密码格式、填充量均不变，不增加“关闭安全检查”选项。不要求用户选择平台，由程序自动检测。
包README和CLI帮助仅在平台验收通过后更新支持声明。

### 4.4 兼容、迁移与回退

- 配置v1和32字节主密钥不变，现有加密配置无需迁移。保留旧版本生成的合成夹具验证读取。
- 先抽象并验证Linux行为不变，再增加新平台，最后接入互操作CI，避免一次性替换所有存储逻辑。
- 新平台能力缺失时明确拒绝相关操作，不退回覆盖式移动、普通链接跟随或宽松权限。
- 回退版本不修改已生成包和配置；新平台若回退到首版将不能打包，应在发布说明中标明。
- 本次实现更新代码、README状态说明和本方案进度；首版历史验收保持不变。

### 4.5 验证设计

**CI的含义**：拟使用GitHub Actions，在PR及push时自动建立原生系统环境、安装依赖、构建和运行测试。
CI是自动执行机制，并不自动证明跨系统产物兼容。

**交叉验证的含义**：一个平台生成的配置与包，传到另一个平台验证读取与还原；这里不是机器学习的交叉验证。

拟新增 `.github/workflows/private-pack.yml`，拆为三类作业：

1. 原生测试矩阵：覆盖目标OS/架构与Python版本，使用uv锁文件安装，执行新工具测试、构建与wheel安装冒烟。Linux继续执行全仓回归；其他系统不把仓库中无关的Linux专属工具视为本功能跨平台支持对象。
2. 生产者：Linux、macOS、Windows分别用合成目录生成一批包、加密配置、临时测试密钥和期望文件哈希。产物带平台、提交及版本标识。
3. 消费者：每个平台下载全部生产者产物，使用同一测试密钥解密配置，再用独立7-Zip解压并比对字节。三种OS形成3×3组合，包含6条跨系统方向；macOS架构在原生矩阵分别验证。

CI只使用可公开的合成数据及一次性测试密钥，不读取仓库密钥或用户资料。上传的测试密钥
与测试包可以一起分发，因为它们仅是互操作夹具，不承载秘密；生产秘密不得放入artifact。
artifacts使用最小必要保留期、独立名称并校验来源提交与摘要；脚本不执行解密配置中的代码或任意路径。
使用只读仓库权限，避免以带秘密的pull_request_target运行未受信代码；Action版本固定到审核过的提交。

| 验收项 | 对应目标 | 场景与预期行为 | 验证方式 | 覆盖边界 |
| --- | --- | --- | --- | --- |
| A1 | G1 | 三个平台完整执行keygen、默认/显式输出pack、decrypt-config | 原生CLI和wheel冒烟 | 记录OS、架构与Python版本 |
| A2 | G2 | 既有及打包期间出现的目标均不被覆盖 | 原生文件系统并发测试 | 含空目录、非空目录和链接目标 |
| A3 | G2 | 符号链接、junction、父路径替换不造成越界读取；密钥硬链接拒绝 | 原生平台专项测试 | Windows无符号链接权限时不能把必要项静默跳过 |
| A4 | G2 | 密钥/明文配置/暂存仅具预期访问权 | POSIX mode及ACL、Windows DACL检查 | 不以mode数值替代Windows ACL验收 |
| A5 | G2 | 写入、发布、占用失败后无完整假成果，句柄关闭、清理或报告残留 | 故障注入和原生占用测试 | 不覆盖断电恢复 |
| A6 | G3 | 3×3配置解密与独立解包，字节一致；错误密码/密钥失败 | CI生产者与消费者artifact交换 | 合法且无名称冲突的公共夹具 |
| A7 | G1/G3 | 中文/空格/空文件/空目录、路径边界、旧配置v1可读 | 原生及旧版夹具测试 | 特殊名称行为单独记录，不静默更名 |
| A8 | G4 | 质量检查、构建、矩阵运行和证据完整 | CI日志、JUnit、产物哈希 | 必要项跳过/未执行不算通过 |

测试代码按能力拆分：FIFO及POSIX权限测试仅在适用平台执行；Windows增加junction、ACL和占用测试。
跨平台适配需保证共同业务测试三个系统都运行；只有不适用项可明确跳过。
独立7-Zip是CI必需测试依赖，缺失时验收失败而非跳过。
拟新增 `docs/private-pack-cross-platform-validation.md` 汇总各平台结果、CI run链接及产物摘要；当前尚无该报告。

### 9.2 跨平台实现与本机验证（2026-11-04）

- 拆分storage_linux、storage_posix、storage_macos、storage_windows，业务层使用统一接口。
- 排他发布在打包前用私有夹具探测，实际提交仍调用原生排他接口；没有覆盖式回退。
- Windows采用ctypes，无新增运行依赖。所有API显式声明参数和返回类型，避免64位句柄截断。
  逐级打开并持有父目录句柄、不共享删除权限；实际文件拒绝重解析点，并把句柄所有权交给CRT/Python流。
  只接受本地NTFS；CREATE_NEW/CreateDirectoryW创建时设置受保护DACL，仅允许当前用户和LocalSystem。
- POSIX密钥与源文件逐组件拒绝链接；私有创建使用父目录fd及dir_fd。
  Linux默认ACL受0600/0700 mode掩码限制；macOS在创建前拒绝父目录上的任何扩展ACL，
  包括无害ACL。这是保守限制，不尝试推断继承ACE的权限效果。
- Windows文件身份继续用CPython的stat/fstat卷号和文件索引，原生测试覆盖硬链接。
  实现依据见验收报告；不使用DirEntry.stat的零值身份作替代。
- 临时目录清理失败抛出包含残留路径的PackError；不假报清理成功。
