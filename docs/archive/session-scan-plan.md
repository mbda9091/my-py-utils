## 1. 结论摘要

- 已新增 `packages/session-scan`，提供 `session-scan` 命令，接入 uv workspace 和聚合安装包。本文的“插件”以独立 CLI 包交付，可由其他插件或 Skill 调用；本轮不另外建设宿主插件界面。
- 只枚举实际存在的 Codex JSONL 和 DSH JSONL / Zstandard 压缩 JSONL。无文件的数据库会话直接忽略，不恢复、导出或补造文件。
- 工作目录和时间条件均可单独使用；同时提供时取交集。工作目录默认包含子目录；时间筛选依据文件内部的用户、助手消息事件时间，不依据最后更新时间或文件 mtime。
- 按条件自动选择读取深度：无时间条件只解析头部及必要索引；有时间条件先筛目录，再流式读取消息，首次有效命中即停止该文件。
- stdout 固定输出一个 JSON 对象，列出文件绝对路径、来源、标题、会话 ID、工作目录和首个命中的消息位置；不提供格式选择参数。完整命中统计、时间范围及对话片段输出留作后续扩展，不为未请求的内容扫描全文。
- 文件是结果单位。同一会话的不同版本、历史分页文件分别保留，不因会话 ID 相同而丢掉文件。
- M1–M3 已实现、提交并完成本机验收；最终版本及产物已对账，结果见 9.6。本方案按完成结果归档，使用说明继续维护。

## 2. 范围与完成条件

### 2.1 目标

用户能通过一条本地命令列出 DSH / Codex 会话记录文件，按任意一个或多个工作目录、消息开始时间、消息结束时间缩小范围，并得到稳定、可供脚本消费的路径或结构化结果。长会话即使最后更新于查询时间段之外，只要内部有该时间段的有效消息，仍应命中。扫描按需读取且保持只读，不启动、恢复或修改会话。

首版面向本机 macOS、Python 3.11+，使用 Python 标准路径接口，避免绑定本机用户名或绝对安装位置。其他系统未真实验证时不声称完成跨平台验收。

### 2.2 非目标

无 JSONL 会话的枚举、数据库正文读取、JSONL 导出或修复、正文关键词搜索、MR / Docs 提取、workspace 台账写入、会话恢复、云端扫描、监控及增量缓存均不在本轮范围内。首版只定位文件及首个命中，不输出完整命中数量、全段首末时间或对话正文；以后明确需要这些结果时再增加相应读取模式。按消息时间筛选所必需的 JSONL 逐行解析属于本轮范围。只解析头部或读取至首次命中，都不代表整份历史完整或可恢复。

### 2.3 完成条件

第 8 节必要验收项全部通过，包安装与入口可用，真实 DSH 压缩文件和 Codex 文件的筛选结果可与源数据对照；记录真实实现 commit 和验收基线后才标记完成。未提交时即使本地验证通过，也保留“待验收，验收通过待提交对账”。

## 4. 具体方案

### 4.1 命令与参数

下列目录和消息时间筛选参数已实现并通过验收，安装工作区依赖后可在仓库根目录运行：

```bash
# 工作目录及其子目录
uv run session-scan --directory ~/Code/project

# 精确匹配，多个工作目录取并集
uv run session-scan --directory ~/Code/a --directory ~/Code/b --exact-directory

# 查找内部有 11 月 19 日或 20 日消息的文件
uv run session-scan --since 2026-11-19 --until 2026-11-20

# 组合条件
uv run session-scan --directory ~/Code/project --since 2026-11-01

# 指定来源或存储位置
uv run session-scan --source codex --codex-home ~/.codex
uv run session-scan --source dsh --dsh-root ~/.dsh/sessions
```

| 参数 | 规则 |
|---|---|
| `--directory PATH` | 可重复；按会话工作目录匹配，多个目录取并集；省略则不筛工作目录 |
| `--exact-directory` | 仅目录本身；未给 `--directory` 时为参数错误 |
| `--since VALUE` | 可省略；按内部消息时间筛选，起点包含，支持日期或带时区偏移的 ISO 8601 时间 |
| `--until VALUE` | 可省略；按内部消息时间筛选，日期包含当日整天，精确时间为排他终点 |
| `--source all\|dsh\|codex` | 默认 `all` |
| `--codex-home PATH` | 优先显式参数，再非空 `$CODEX_HOME`，最后 `~/.codex` |
| `--dsh-root PATH` | DSH 会话文件根目录，默认 `~/.dsh/sessions`；首版不增加环境变量或配置文件 |

未传目录和时间条件时，列出所选已知存储根下的全部可识别会话文件，不递归扫描整个 home 或项目源码。所有查询均直接输出 JSON，不需要 `--format` 参数。

### 4.2 发现与元数据

流程：解析参数并决定读取需求 → 定位存储根 → 枚举候选文件 → 读取会话头及必要索引 → 先筛工作目录 → 若有时间条件则逐行检查消息，首次命中即停止该文件 → 排序去重 → 输出。

| 查询需求 | 读取行为 | 停止条件 |
|---|---|---|
| 无时间条件，包括只给目录或不传筛选 | 只读会话头及必要索引，不解析正文消息 | 文件头足以判定目录和元数据后即停止 |
| 只给时间 | 头部确认来源 / ID 后，流式检查内部消息时间 | 首次有效命中即停止；无命中需读完本次文件范围 |
| 目录与时间组合 | 先以头部 / 索引 cwd 排除无关文件，只扫描剩余文件的消息 | 目录不匹配则不读正文；匹配后首次有效命中即停止 |
| 完整统计或对话内容输出（后续扩展） | 由显式输出需求触发更深入扫描 | 必须满足所请求统计或内容的范围，不能将首次命中伪装成完整结果 |

此分流由筛选条件确定，不增加模型调用，也不让用户手动选择“浅扫 / 深扫”。固定 JSON 输出本身不触发正文读取。

**Codex：**

1. 递归枚举 `<codex-home>/sessions` 和 `<codex-home>/archived_sessions` 下的 `*.jsonl`。归档、父代理、子代理文件同等参与筛选。
2. 首行须为 `session_meta`，从 payload 读取会话 ID 和 cwd。文件有有效头部，即使没有数据库索引，也可进入结果。
3. `state_5.sqlite` 若存在，仅用只读连接、读事务按已发现的 ID 读取 `threads` 的 ID、cwd、name、title 和更新时间列，不读取 first_user_message、preview 等消息内容列或 `thread_history_*.sqlite`。cwd 优先有效的 `threads.cwd`，其次头部 cwd；标题优先非空 `name`，再 `title`，否则为空。
4. cwd 来源冲突时采用上述优先级并发出告警，结构化结果记录来源。索引仅用于补充已发现文件，不跟随其路径到扫描根外，也不输出其无文件记录。
5. 数据库不存在时正常使用文件头，标题可为空；消息时间始终来自文件内部。数据库存在但损坏或相关结构不支持时报告错误，继续按文件信息扫描并返回部分失败。

**DSH：**

1. 在指定根中识别 `session.jsonl`、`session.v3.jsonl`、`session.v4.jsonl` 及对应 `.zstd` 文件；其他命名不按普通会话文件猜测。
2. 使用 Python `zstandard` 流式解压 Zstandard 文件，实施时通过 `uv add --package session-scan zstandard` 声明运行时依赖，不要求用户另装 `zstd` 命令。
3. 头部须为 `type=session`，支持已调研的版本 0、3、4，读取 ID 和 cwd。遇到 `session.vN.jsonl[.zstd]` 的未知版本，应报告不支持，不能静默当成已支持版本。
4. 首版不为生成标题额外读取正文；头部没有标题时返回空值，不用文件夹名称冒充工作目录或会话标题。

两种来源的首条解码后 JSON 最大 1 MiB，超限报告 `header_too_large`。无时间条件时到头部即止；时间条件要求读取正文时，逐行解码且不将全文载入内存，DSH 同步按需流式解压。消息扫描每行解码后上限为 16 MiB，超限报告 `record_too_large` 并将该文件标记为扫描不完整；不把无法解析的大记录算成正常无命中。

读取器允许有限的底层缓冲预读，但不得主动遍历或解压剩余正文。早停后未访问区域及压缩尾部不做完整性保证；错误报告只覆盖本次实际读取范围。

### 4.3 工作目录规则

- 筛选依据是结构化会话 cwd，不搜索对话中出现的路径或工具的临时执行目录。
- 用户输入展开 `~`，相对路径相对命令启动目录转换为绝对路径，词法规范化 `.`、`..` 和分隔符。历史筛选目录无需仍然存在。
- 不解析符号链接、不折叠大小写。按路径组成部分判断相等或子目录，`project-backup` 不属于 `project`。
- 会话 cwd 必须为有效绝对路径；缺失或相对路径记为未知。不猜测其相对基准。
- 有目录条件时排除未知 cwd，并在摘要计数；仅按时间或无筛选时可保留未知 cwd 文件。
- 子代理按自己的 cwd 匹配，不因父会话命中而带入其他目录。多个目录 OR，目录条件与时间条件 AND。

### 4.4 内部消息时间与按需扫描

本轮时间条件定义为：**文件内至少有一条可识别的用户或助手消息，其记录时间位于查询区间内**。不因会话最后更新时间或 mtime 落在区间外而提前排除；也不采用“会话最早时间到最晚时间覆盖区间”代替实际消息命中。

| 来源 | 消息事件及时间 | 不计入时间命中的记录 |
|---|---|---|
| Codex | 按来源版本识别用户 / 助手消息，使用该消息记录的顶层 `timestamp`；包括支持的 `response_item/message`（user / assistant）、`event_msg` 消息及结构化 UserMessage / AgentMessage 事件 | 会话头、配置、系统提示、reasoning、工具调用 / 返回、token 统计及其他非对话事件 |
| DSH | 按版本识别 `user/message`、`assistant/message` 及对应历史版本消息，使用事件 `time` 毫秒时间戳 | session 头、配置、system/message、request/context、工具事件及可明确识别的 seed / replay 上下文 |

已结合真实结构和本地安装包的格式代码固化消息白名单，细节见 [新包 README](../../packages/session-scan/README.md)。Codex paginated 模式只将原生消息事件 / 完成条目当作新对话，排除 response item 上下文镜像和带 retained / replay 标记的记录；legacy 模式额外支持 response item 消息。DSH 0 / 3 / 4 仅接受 `surfaceOp=append` 且来源为 user / model 的相应消息；明确的配置、插件注入、replacement 和 streaming packed delta 不计作独立对话。M2 实查并补充 runtime-context、time-context、tool-jobs 三种 user 角色上下文来源，它们不作为用户发言。模型来源内的 `replayState` 是提供商状态，不因该字段存在而错误排除实时模型消息。

不能因任意 JSON 对象含时间字段就当成消息。缺少足够来源信息而无法判断的 DSH 候选消息，报告 `ambiguous_message_origin`，不作为确定命中。未知 Codex history mode 明确报告不支持。时间表示来源记录的事件时间，不承诺所有恢复 / 导入数据均保留真实发送时刻，不按文本相同去重或猜测新旧消息，也不在本轮重建未保留最终消息的历史 delta。

读取与早停规则：

1. 无 `--since` / `--until` 时不启动消息迭代器；JSON 结果只取头部及可用索引元数据。
2. 有时间条件时先完成工作目录筛选；被目录条件排除的文件不解析正文。
3. 从头部后按原始记录顺序扫描，只有有效消息及有效事件时间都满足条件才命中。JSON 文件列表只需要存在性判断，找到第一条即停止该文件，不继续计算总数或完整范围。
4. 无命中需扫描到本次读取范围结束。不能假定时间单调；遇到一条晚于上界的记录不能直接结束，否则可能漏掉后续较早的消息。
5. 无时间戳或时间格式非法的消息不使用 mtime、索引时间、当前时间代填；记录 `missing_message_time` / `invalid_message_time`，该文件的时间判断标记为不完整。可继续找到其他有效命中，但最终仍返回部分失败。
6. 读取错误、损坏记录或来源不明使扫描不完整时，未命中文件记为 `indeterminate`，不能算“已确认无命中”；其他可读文件继续扫描。首次命中之后未访问部分不纳入错误或完整性结论。

**seeded 文件的必要边界读取：**旧 `seedLength` 可直接用于排除继承 seq；新 `isSeeded=true` 文件的权威继承边界可能在后文，不能在边界未确定前将早期消息算成该会话的新发言。因此仅在请求消息读取时，先用有界流预扫至该文件范围结束，确定最后一个 `data.inherited=true` 的 `session/end-seed`，再在同一打开源及初始长度内重置流、惰性迭代边界之后的消息。预扫失败或缺少边界时报告不完整，不输出误归属消息。后续匹配仍可首次命中即停；仅读目录 / 头部的调用完全不进行此预扫。该例外是读取已继承历史所必需，不增加默认全文扫描。

日期和区间边界：

- 日期 `YYYY-MM-DD` 使用命令运行时系统本地时区；`--since` 从该日零点开始，`--until` 转成次日零点的排他上界。跨夏令时按当地日历日处理，不能固定加 24 小时。
- 精确时间接受带偏移或 `Z` 的 ISO 8601，如 `2026-11-20T10:00:00+08:00`；不接受无时区的精确时间。
- 内部统一比较 UTC 时间，命中时间以 UTC ISO 8601 输出；JSON 摘要记录解析后的上下界及起止日期各自所用本地时区偏移。
- 可只给起点或终点。非法日期、空参数、转换后的起点不小于终点均返回参数错误；同一天的起止日期表示该完整自然日，合法。
- 同时给目录与时间条件时，两者必须同时满足；无时间条件不验证正文的消息时间，也不报告未访问正文的时间缺失。

### 4.5 输出契约

以文件为粒度，按 `(source, 词法规范化绝对路径)` 去重；不按标题、会话 ID 或内容去重，不折叠硬链接与符号链接别名。不同真实路径对应同一会话时分别列出。

无时间条件时，仅为展示和排序保留 `updated_at`：Codex 有效索引 `updated_at_ms` 优先、其次 `updated_at`，缺失则回退文件 mtime；DSH 使用文件 mtime，附 `updated_at_source`。这些元数据不触发正文读取，也不参与消息时间筛选。

无时间条件按 `updated_at` 降序，再按来源和绝对路径升序；有时间条件按首个扫描命中记录的 `timestamp` 降序，再按来源和路径升序。这里的“首个”是文件顺序上的第一个有效命中，不声称是时间最早或最晚的一条。

- stdout 固定为单个 JSON 对象，包含 `schema_version=1`、`status`、`filters`、`results`、`summary`、`warnings`、`errors`；不混入标题、表格、进度或纯路径行。必要诊断可写 stderr。
- 结果字段包括 `source`、`session_id`、`title`、`cwd`、`cwd_source`、`path`、`updated_at`、`updated_at_source`、`match`；未知标题或 cwd 用 `null`。无时间条件 `match=null`；有时间条件 `match` 含 `timestamp`、`time_source`（`codex_event_timestamp` / `dsh_event_time`）、`line_number`（含头部，从 1 开始）、可用的原始 `ordinal` / `seq` 和 `scan_state`（`first_match` / `first_match_with_errors`）。压缩文件行号指解压后的 JSONL，不冒充压缩字节偏移。
- 路径和标题通过标准 JSON 序列化保留原值，换行、回车等字符正常转义，不因旧纯路径输出的限制跳过文件。
- 不输出未经完整扫描的总消息命中数、完整首末时间或正文。告警与错误包含稳定的 `code`、来源路径及可读 `message`，不附带正文；索引时间与消息命中时间的字段名称明确区分。

零命中时仍返回 JSON 对象，其中 results 为空数组；无读取错误时返回 0。摘要分别记录候选文件数、头部有效文件数、匹配文件数、目录排除数、未知 cwd 排除数、已确认时间无命中文件数、时间判断不完整文件数、仅读头部文件数、正文扫描文件数、首次命中早停文件数和错误数，不能把文件数说成去重会话数。时间判断不完整可与有效命中重叠，必须注明这些计数不是互斥分区。

### 4.6 异常与只读边界

- 默认根不存在时告警并继续其他来源；所选来源均不可用时返回 2。显式指定根不存在或不是目录时返回 2，不自动创建。
- 单个文件无权限、损坏头部、不支持版本、实际访问的消息记录损坏或时间无法判断、解压失败、扫描目录不可读或扫描期间消失时记录错误，继续其他文件，最终返回 1。忽略无文件的索引本身不产生错误或逐条告警。
- 候选必须是常规文件；首版不递归跟随目录符号链接，拒绝读取指向所选根之外的文件符号链接并报告。用户显式传入的根若是符号链接，以其解析后的目标作为允许范围；cwd 匹配仍使用词法规则。
- 不读认证配置、附件及正文数据库，不写源文件或数据库，不执行历史记录中的命令。读取完即关闭文件、解压流和数据库连接，不追赶活动文件的追加内容。
- 对活动文件，打开时固定源字节长度，只扫描该范围；DSH 对压缩源限制实际读取字节范围，正常压缩帧尚未结束或 JSONL 活动尾行不完整时，标记扫描不完整，不误报完整无命中。提前命中则关闭流，不继续检查尾部。不保证文件随后仍存在，也不承诺跨文件、数据库的全局同刻快照。
- 退出码：`0` 扫描完成（允许零命中及默认来源缺失告警）；`1` 部分读取或输出失败；`2` 参数或启动数据源无效；`130` 用户中断。中断不承诺完整 JSON，自动化调用方必须检查退出码。
