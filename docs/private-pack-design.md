## 1. 结论摘要

- **要解决的问题**：按输入目录的一级条目分别创建加密压缩包，通过随机名称和加密配置保存名称、密码映射。
- **采用的方案**：先在内存生成配置，再打包、重命名，最后加密配置并整批提交输出。
- **已定参数**：7z内容和文件名加密；每批统一20位数字及大小写字母密码；每包16字节随机填充；AES-256-GCM加密配置。
- **本轮边界**：解密仅恢复配置，源文件不变；不实现自动恢复包名、解压、续跑或并行。
- **当前进展**：M1–M4及A1–A9均完成Linux本机验收；历史检查与修正见第9节，证据见验收报告。
- **下一步**：本轮范围内无未完成事项；按包README使用。跨平台与自动恢复仅在另行提出需求时建设。

## 2. 范围

### 2.1 目标

- G1：用户能将每个一级子目录或文件分别打成加密包，内部名称受保护，源内容完整可还原。
- G2：每批统一密码、最小随机填充和随机包名，映射只保存在加密配置中。
- G3：用户持独立主密钥解密配置，获取原名、批次密码及校验信息。
- G4：失败不覆盖已有文件、不发布缺少配置的最终成果，接入现有workspace工具链。

### 2.2 非目标与延期项

| 事项 | 本轮处理 | 原因或触发条件 |
| --- | --- | --- |
| 自动恢复包名、解压和删除填充 | 延期 | 用户明确首版仅解密配置，另行提出恢复需求时评估 |
| 断点续跑、并行、GUI | 不做 | 首版串行整批处理 |
| 格式伪装、隐藏源文件大小 | 不做 | 仅要求内容加密、名称隐藏和实际重复打包MD5不同 |
| 口令派生主密钥 | 延期 | 首版直接使用32字节随机密钥文件 |
| 跨批次MD5历史库、快照一致性 | 不做 | 不承诺绝对无碰撞或动态源目录快照 |

### 2.3 适用场景与协作边界

- 适用于本仓库的本地Python CLI用户，运行时Python 3.11+，开发与依赖管理使用uv。
- 首轮必验环境为Linux本机；macOS和Windows兼容性未验证，不据本机结果宣称已支持。

## 4. 具体方案

### 4.1 总体设计与职责

处理顺序：扫描 → 内存配置计划 → 加密压缩 → 随机重命名 → 补齐校验信息 → 加密配置 → 整批提交。

下列模块均已实现，位于 `packages/private-pack/src/private_pack/`：

| 部分 | 职责 | 输入与输出 | 改动 |
| --- | --- | --- | --- |
| main.py | 参数、进度和错误出口 | CLI → 包内调用 | 已新增 |
| planning.py | 路径校验、扫描、密码与映射 | 输入目录 → 内存计划 | 已新增 |
| archive.py | 填充、7z加密与哈希 | 条目计划 → 完成的压缩包 | 已新增 |

### 4.2 输入输出与关键行为

输入示例：

```text
input/
├── 项目A/
│   ├── 文档.txt
│   └── 图片/
├── 项目B/
└── 说明.pdf
```

处理单位与原始包名：

| 处理单位 | 原始包名 | 包内源内容 |
| --- | --- | --- |
| 项目A目录 | 项目A.7z | 保留项目A顶层目录及其全部递归内容 |
| 项目B目录 | 项目B.7z | 保留项目B顶层目录，包括空目录 |
| 说明.pdf文件 | 说明.pdf.7z | 保留说明.pdf原名 |

隐藏文件与隐藏目录同样处理。空输入目录报错；符号链接和特殊文件明确报错，
不跟随链接读取范围外内容。扫描和打包期间都需检查文件类型。

最终输出示例：

```text
output/
├── 3fc91d7a8b024e62a9c6d1873a50f421.7z
├── <随机标识2>.7z
├── <随机标识3>.7z
└── manifest.enc
```

`pack --output` 可省略，默认在输入目录同级生成“输入目录名-packed”；显式指定时优先使用该路径。
输入为 `.` 或带末尾斜杠时按解析后的目录名命名；文件系统根目录必须显式指定输出。
输出目录必须不存在，且位于输入目录之外；路径检查应解析实际路径。
随机标识由安全随机源生成，使用16字节随机值的32位十六进制表示，批次内检查唯一性。
原始包名仅用于临时打包与配置映射，最终包名不额外执行可逆加密。

### 4.3 密码与最小填充

#### 4.3.1 整批统一密码

每份配置仅在顶层保存一个 `archive_password`，该批次所有压缩包共用此密码。
每次新建批次重新生成密码，不为每个包单独生成密码。

密码长度固定20位，字符集仅包含 `0-9`、`a-z`、`A-Z`，并保证三类字符都出现。
使用 `secrets` 安全随机源从62个字符中采样；若不包含全部三类，则重新采样。
密码不写入日志、不作为命令行参数传递、不输出到终端。

压缩包密码与配置加密主密钥是两个独立秘密，不互相派生。

#### 4.3.2 最小化填充

每包固定加入一个16字节随机内容文件，使用 `secrets.token_bytes(16)` 生成，
每次打包重新生成。填充文件放在包内根目录，名称使用随机标识并检查与源内容不冲突。
填充文件路径和长度写入配置，随机内容本身无需保存。

填充仅用于让重复打包的字节内容和MD5在实际使用中不同，不负责隐藏源文件大小。
取消原方案的1～16 MiB随机大小填充及相关CLI参数。
16字节提供128位随机空间，同时将内容开销保持很小；压缩包目录项和加密结构还会产生额外开销。

“MD5不同”是工程上的概率保证，不是数学上的绝对保证：随机内容可能重复，
不同字节也可能发生MD5碰撞。不为此维护跨批次历史哈希库。
验收时对同一输入重复打包并检查MD5不同；正式完整性记录使用SHA-256。

### 4.4 压缩与配置契约

固定输出7z格式，使用 `py7zr` 的内置内容加密及头部加密（内部文件名加密）。
显式启用 `header_encryption=True`，使用同一批次密码，压缩采用LZMA2。
压缩包外部仍能被识别为7z格式，内部名称和内容由加密保护。

配置先在内存生成完整计划，不要求写入明文临时文件。示例：

```json
{
  "version": 1,
  "archive_format": "7z",
  "archive_password": "<20位数字和大小写字母组合>",
  "entries": [
    {
      "source": "项目A",
      "kind": "directory",
      "original_archive_name": "项目A.7z",
      "archive_name": "3fc91d7a8b024e62a9c6d1873a50f421.7z",
      "padding": {
        "archive_path": "_padding_76ac.bin",
        "size_bytes": 16
      },
      "archive_size": null,
      "archive_sha256": null
    }
  ]
}
```

`source` 是相对输入目录的路径，不保存机器绝对路径。
原名、随机目标名、密码和填充计划在打包前确定；大小与SHA-256在包关闭后计算并补齐。
最终加密配置不允许存在未完成条目或空的结果字段。

逐包在独立私有临时子目录内用原名创建，避免原始包名冲突，再移至批次暂存目录的随机名称。
源数据直接读取，不复制整份源目录；填充文件如需落盘，只写入私有临时目录。
首版串行处理。检测到打包期间源文件变化时失败，不宣称提供快照一致性。

### 4.5 配置加密与CLI

使用 `cryptography` 的AES-256-GCM加密整个UTF-8 JSON配置。
主密钥为安全随机生成的32字节密钥文件，第一版不支持人类口令派生主密钥。

加密文件格式：固定格式标识、版本号、12字节随机nonce、密文及16字节认证标签。
格式标识与版本号作为AAD参与认证；每次加密重新生成nonce，不重复使用固定nonce。
解析时拒绝未知版本、截断及不合法结构，认证失败不输出明文。

主密钥不写入配置、不复制到输出目录，也不得位于输入目录内。
密钥文件与加密配置需分别保管、备份；缺失任一项可能无法取得解压密码。
在支持POSIX权限的平台，密钥文件和解密配置文件使用0600权限，私有临时目录使用0700。
其他平台按可用的文件权限机制处理，不宣称POSIX权限等价于跨平台访问控制。

打包流程不主动将明文配置落盘。此承诺不包含操作系统交换区或崩溃转储等内存副本。

以下命令已实现。示例路径为占位符，使用前替换为实际路径；先运行 `uv sync --all-groups --all-packages`，或安装聚合包。输出父目录必须已存在：

```bash
# 首次生成主密钥，拒绝覆盖已有文件
private-pack keygen --output "<secrets>/master.key"

# 批量打包，密码自动生成，填充固定16字节
private-pack pack "<data>/input" \
  --output "<data>/output" \
  --key-file "<secrets>/master.key"

# 仅解密配置，显式输出明文JSON，不打印内容
private-pack decrypt-config "<data>/output/manifest.enc" \
  --key-file "<secrets>/master.key" \
  --output "<secrets>/manifest.json"
```

解密配置先在内存认证并校验结构，成功后才创建输出，拒绝覆盖已有文件。
命令输出进度、处理数量和结果位置，不泄露密码、密钥或配置正文。

### 4.6 整批提交与异常路径

1. 校验路径、密钥、输入类型及输出不存在，扫描所有处理单位。
2. 在内存生成配置计划。
3. 在最终输出目录旁创建私有临时目录，保持与输出位于同一文件系统。
4. 逐包创建、关闭、随机重命名并计算结果信息。
5. 加密最终配置为 `manifest.enc`，重新解密校验其与内存配置一致。
6. 清理中间文件，通过Linux `renameat2(RENAME_NOREPLACE)` 将完整暂存目录提交为最终输出目录；并发出现的目标也拒绝覆盖，不退化为普通覆盖式rename。

提交前失败不发布最终目录；普通异常清理本次创建的临时产物，不删除用户原有文件。
强制终止可能留下不完整临时目录，由用户清理后重新运行。
由于第一版不支持续跑，内存配置丢失后的临时压缩包不作为可恢复成果。
源文件始终可用于重新打包。最终目录只有在压缩包与加密配置全部就绪时才出现。
