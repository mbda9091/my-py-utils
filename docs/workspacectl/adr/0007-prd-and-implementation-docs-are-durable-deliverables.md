# Durable task deliverables are requirements and implementation docs

A task does not keep a full execution snapshot. After cleanup, the durable outputs are the worktree `doc/` tree, moved under `doc/<task-root-name>/` with original filenames and relative directory structure preserved; when a requirement spans multiple worktrees, each worktree keeps its own first-level archived directory name beneath that root. Today that tree mainly contains the requirement document generated inside the worktree from the source PRD and the implementation document generated by `grill-with-docs`. The implementation doc must include a compact execution review appendix so the process can be rechecked later without keeping a separate trace file. The source PRD itself is not stored in full; only its URL is kept.

The appendix field list and verification shape are defined in
`docs/workspacectl/execution-runbook.md`.

## Consequences

- The workspace keeps human-facing deliverables, not session traces.
- Worktree-local state remains disposable.
- No fixed rename is imposed during document migration.
- The original PRD content stays outside the workspace docs.
- Process reviewability comes from the implementation doc appendix, not from a third durable artifact.
